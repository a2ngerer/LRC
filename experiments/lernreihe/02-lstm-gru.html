LSTM & GRU:
das Neuron lernt zu behalten

Vorlesung 01 hat gezeigt, warum ein gewöhnliches RNN vergisst: der Gradient läuft durch ein Produkt vieler Jacobi-Matrizen und schrumpft auf null. LSTM und GRU lösen das nicht mit einem Kniff, sondern mit einem zweiten Pfad: einem additiven Speicher, durch den der Fehler ungedämpft zurückfließt — das Constant Error Carousel.

Worum es geht

Eine Tür, die der Fehler offen findet

Stell dir einen Notizzettel vor, den ein Sachbearbeiter über viele Schritte weiterreicht. Beim gewöhnlichen RNN wird der Zettel bei jeder Übergabe neu abgeschrieben — und mit jeder Abschrift verblasst er, bis nach zwanzig Stationen nichts mehr lesbar ist. Das LSTM legt daneben eine geschützte Schublade: Was hineingelegt wird, bleibt dort liegen, bis ein Gate es bewusst löscht. Der Fehler-Gradient findet diese Schublade beim Rückwärtslaufen offen.

Diese Vorlesung baut die Brücke von Vorlesung 01 zu allem, was folgt. Das Vanishing-Gradient-Problem war dort die Wurzel; hier steht die erste echte Lösung. Und der additive Speicherpfad c, den wir gleich herleiten, ist genau der Pfad, um den Vorlesung 05 (Mixed Memory) später eine ODE-Zelle legt.

Das Versprechen dieser Seite

Am Ende verstehst du drei Dinge konkret: (1) warum der additive Zellzustand c_t = f·c_{t-1} + i·g den Gradienten rettet (das CEC), (2) wie Input-, Forget- und Output-Gate diesen Speicher steuern und wie die GRU dasselbe mit weniger Bauteilen erreicht, und (3) dass die LSTM/GRU im Thesis-Code diskret sind — sie werfen die verstrichene Zeit weg, anders als die kontinuierlich-zeitlichen ODE-Zellen.

Jedes Lab rechnet die skalare Reduktion der echten Gate-Gleichungen aus stepLSTM bzw. stepGRU der geteilten Engine.

01  Woher das Problem kam

Der Gradient läuft durch ein Produkt — und stirbt

Kurzer Rückblick auf Vorlesung 01: Beim Backpropagation Through Time entsteht der Gradient über viele Zeitschritte als Produkt von Jacobi-Matrizen. Jeder Faktor enthält die Ableitung der tanh-Aktivierung, und die liegt zwischen 0 und 1. Ein Produkt aus vielen Zahlen kleiner 1 geht gegen null Paper · Hochreiter1997.

Vanilla-RNN · BPTT-Gradient (aus VL 01)klassisch

Die Kernidee von LSTM dreht genau diesen einen Faktor um. Statt eines tanh-Updates, das den Zustand bei jedem Schritt komplett neu schreibt, gibt es einen Zustand, der sich additiv fortpflanzt: c_t = f·c_{t-1} + …. Wenn das Forget-Gate f≈1 ist, ist die Ableitung ∂c_t/∂c_{t-1}=f≈1 — der Produktfaktor wird nicht mehr kleiner. Das ist das Constant Error Carousel.

Die eine Zeile, auf die es ankommt

Vanilla-RNN: ∂h_t/∂h_{t-1} enthält tanh'·W_h → typischerweise < 1 → Produkt zerfällt. LSTM: ∂c_t/∂c_{t-1} = f_t, ein Gate-Wert nahe 1 → Produkt bleibt nahe 1. Der Gradient hat eine Datenautobahn bekommen.

02  Vier Gates, ein Speicher

LSTM: drei Türen für eine Schublade

Das Long Short-Term Memory Paper · Hochreiter1997 führt einen zusätzlichen Zustand ein: die Zelle c, getrennt vom sichtbaren Hidden State h. Drei Sigmoid-Gates entscheiden, was geschrieben, behalten und gelesen wird; ein tanh liefert den Kandidaten:

LSTM · die vier TorePaper
LSTM · Speicher- und Lese-Schritt (der CEC steckt hier)Paper

Lies die erste Gleichung als zwei Hebel auf derselben Schublade: f_t bestimmt, wie viel vom Alten überlebt, i_t·g_t, wie viel Neues dazukommt. Steht f≈1 und i≈0, bleibt der Inhalt Schritt für Schritt unverändert liegen — perfektes Gedächtnis. Genau das ist im Code so umgesetzt Code · engine.js · stepLSTM:

engine.js · stepLSTM (skalare Reduktion)vier Gates + c-Pfad
function stepLSTM(state, x, p){
    const h = state.h||0, c = state.c||0;
    const i = sig(p.wix*x + p.wih*h + p.bi);   // Input-Gate
    const f = sig(p.wfx*x + p.wfh*h + p.bf);   // Forget-Gate
    const o = sig(p.wox*x + p.woh*h + p.bo);   // Output-Gate
    const g = tanh(p.wgx*x + p.wgh*h + p.bg);  // Kandidat
    const nc = f*c + i*g;          // additiver Speicherpfad — der CEC
    const nh = o*tanh(nc);
    return {h:nh, c:nc, i, f, o, g};
}

Die hervorgehobene Zeile ist das Herz: f*c ist die direkte Durchreichung des alten Speichers — keine Matrixmultiplikation, kein tanh dazwischen. Code · engine.js · stepLSTM

Dreh am ersten Lab: schick ein Signal durch die LSTM und beobachte die drei Gates live. Schalte das Signal auf still und stell das Forget-Bias hoch — der Zellzustand c bleibt eingefroren stehen. Das ist die Schublade in Aktion.

03  Warum der Gradient überlebt

Das Constant Error Carousel, gezeichnet

Zwei Pfade laufen durch ein RNN. Beim Vanilla-RNN ist der einzige Pfad multiplikativ: jeder Schritt presst den Zustand durch W_h und tanh, und der Gradient sammelt bei jedem Schritt einen Faktor < 1 ein. Beim LSTM gibt es daneben den additiven c-Pfad, dessen lokale Ableitung das Forget-Gate ist Paper · Hochreiter1997.

CEC · der Gradient entlang des c-PfadsPaper

Im Lab unten siehst du, wie sich der Gradient über die Schritte verhält. Dreh am Forget-Gate: bei f nahe 1 bleibt der LSTM-Gradient (rot) flach, während der Vanilla-Gradient (grau) exponentiell zusammenbricht.

04  Dasselbe mit weniger Teilen

GRU: ein State, zwei Gates

Die Gated Recurrent Unit Paper · Cho2014 fasst die Idee straffer: kein getrennter Zellzustand mehr, nur noch h. Statt drei Toren reichen zwei — ein Reset-Gate r und ein Update-Gate u. Das Update-Gate übernimmt die Doppelrolle von Forget und Input: es mischt alten und neuen Zustand konvex.

GRU · zwei Gates, konvexe MischungPaper

Die letzte Zeile ist der GRU-CEC: steht u≈1, wird h_t ≈ h_{t-1} — der Zustand wird fast unverändert durchgereicht, und ∂h_t/∂h_{t-1}≈u≈1. Derselbe additive Schutz wie beim LSTM, nur in den einen State h gefaltet. So steht es im Code Code · engine.js · stepGRU:

engine.js · stepGRU (skalare Reduktion)reset + update
function stepGRU(state, x, p){
    const h = state.h||0;
    const r = sig(p.wrx*x + p.wrh*h + p.br);      // Reset-Gate
    const u = sig(p.wux*x + p.wuh*h + p.bu);      // Update-Gate
    const hc = tanh(p.whx*x + p.whh*(r*h) + p.bh); // Kandidat, r dämpft alten h
    const nh = (1-u)*hc + u*h;   // konvexe Mischung — u nahe 1 hält
    return {h:nh, r, u, hc};
}

Ein einziger State, eine Mischung statt zweier separater Hebel. Weniger Parameter pro Einheit, oft vergleichbare Qualität. Code · engine.js · stepGRU

Im Lab schickst du dasselbe Signal durch GRU und LSTM und vergleichst, wie lange beide eine Information nach einem Puls festhalten. Beide nutzen denselben additiven Trick — der Memory-Hold-Test zeigt, wie ähnlich sie sich verhalten.

05  Der Kontrast zu den ODE-Zellen

Im Thesis-Code sind LSTM und GRU diskret

Hier liegt der entscheidende Unterschied für die Masterarbeit, und er steht unscheinbar in einer einzigen Zeile. Die Thesis-Wrapper sind dünne Hüllen um tf.keras.layers.LSTMCell bzw. GRUCell — und sie verwerfen die verstrichene Zeit Code · lstm_cell.py:38:

src/neurons/lstm_cell.py · callZeilen 37–41
def call(self, inputs, states):
    if isinstance(inputs, (tuple, list)):
        inputs, _ = inputs   # discard elapsed_time (LSTM is discrete)
    output, new_states = self._lstm(inputs, states)
    return output, new_states

Das _ ist die weggeworfene elapsed_time. Die GRU macht es identisch Code · gru_cell.py:23.

Vergleiche das mit der CTRNN-Zelle, die elapsed_time als echtes dt in ihren Euler-Schritt steckt Code · ctrnn_cell.py:50:

src/neurons/ctrnn_cell.py · call (zum Vergleich)Zeilen 50–58
def call(self, inputs, states):
    if isinstance(inputs, (tuple, list)):
        inputs, elapsed_time = inputs   # dt wird BENUTZT
    else:
        elapsed_time = 1.0
    h = states[0]
    gate = tf.nn.tanh(inputs @ self.W_x + h @ self.W_h + self.b)
    h_new = h + (elapsed_time / (self.tau + self.epsilon)) * (-h + gate)
    return h_new, [h_new]

Bei der CTRNN steht elapsed_time direkt im Update — die Zelle ist kontinuierlich-zeitlich. Bei LSTM/GRU fehlt sie. Code · ctrnn_cell.py:50-57

Warum das für die Thesis zählt

Die ODE-Zellen (CTRNN, LTC, LRC, CfC) sind zeitkontinuierlich: sie können auf unregelmäßig abgetastete Sequenzen reagieren, weil das echte Δt in die Gleichung eingeht. LSTM und GRU behandeln jeden Schritt als gleich weit entfernt — die Zeitachse ist für sie nur ein Schrittzähler.

Genau das macht LSTM und GRU zu den klassischen Baselines des Benchmarks: Sie lösen das Gedächtnis-Problem, aber sie ignorieren die kontinuierliche Zeit, die die liquiden Zellen ausnutzen.
