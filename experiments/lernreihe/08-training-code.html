Vier Funktionen, ein Experiment

Der gesamte Benchmark — alle Zelltypen, alle sechs ODE-Systeme, alle Seeds — läuft durch denselben kleinen Trainings-Kern. Wer ihn versteht, versteht jede Zahl in Vorlesung 09 und 10. Es lohnt sich, langsam zu lesen: hier wird nichts versteckt.

Die Aufgabe ist ungewöhnlich für ein neuronales Netz. Das Modell soll keine Klassen vorhersagen, sondern eine Ableitung. Gegeben ein Zustand y, liefert das Netz dy/dt — wie schnell und in welche Richtung sich das System gerade ändert. Diese gelernte Ableitung wird dann integriert, und die so erzeugte Bahn wird mit der echten Trajektorie verglichen. Das ist die Idee des Neural ODE.

Das Versprechen dieser Seite

Am Ende kannst du den Forward-Pass mitrechnen: (1) wie euler_odeint aus y0 plus der gelernten Ableitung eine ganze Bahn baut und warum ein grobes Δt Fehler erzeugt, (2) wie get_batch aus einer langen Trajektorie zufällige kurze Fenster schneidet, und (3) wie der Loop aus tf.GradientTape, optionalem clip_by_global_norm und Adam einen Gradientenschritt macht.

Jedes Lab rechnet mit demselben eulerOdeint und denselben sechs SYSTEMS wie der echte Code — kein Ersatz, keine Vereinfachung der Integration.

01  Was das Netz lernt

Das Netz modelliert die Ableitung, nicht den Zustand

Bevor irgendetwas integriert wird, muss klar sein, was das Modell überhaupt ausgibt. Das ODEFuncModel Code · ode_model.py ist eine kleine Pipeline aus drei Schichten. Eingang ist ein Zustand, Ausgang ist eine Ableitung gleicher Form:

ode_model.py · ODEFuncModelZeilen 40–50
self.dense_in  = Dense(units)            # Projektion: features -> units
self.rnn       = make_dense_model(neuron_type, units=units, **cell_kwargs)
self.dense_out = Dense(features)         # Projektion zurück: units -> features

def call(self, t, state):           # t ungenutzt: autonome ODE
    h  = self.dense_in(state)        # (batch, 1, units)
    dh = self.rnn(h)               # die Zelle (LTC/LRC/CfC/…) rechnet hier
    dy = self.dense_out(dh)         # dy = f(state): die ABLEITUNG
    return dy

Der Rückgabewert von call ist dy — die rechte Seite der ODE. Genau diese Funktion bekommt euler_odeint als func übergeben. Code · ode_model.py

Das, was das Netz darstelltCode

Welche Zelle in der Mitte sitzt, entscheidet neuron_type: eine LTC aus Vorlesung 03, eine LRC, eine CfC aus 04, ein LSTM aus 02. Die Hülle bleibt immer dieselbe. Damit ist der Vergleich fair — nur der Kern wechselt, der Rest des Trainings ist für alle identisch.

Warum „autonom“ und warum t ungenutzt ist

Die sechs Benchmark-Systeme aus Vorlesung 07 sind autonom: ihre rechte Seite hängt nur vom Zustand y ab, nicht direkt von der Zeit t Code · datasets.py. Deshalb ignoriert call(t, state) das Argument t und füttert nur den Zustand durch das Netz. Das Argument bleibt nur stehen, damit die Signatur zu euler_odeint passt.

02  Der Forward-Pass

euler_odeint baut die Trajektorie

Das Netz liefert nur die Steigung an einem einzigen Punkt. Eine ganze Bahn entsteht erst, wenn man diese Steigung Schritt für Schritt aufsummiert. Genau das macht euler_odeint Code · solver.py — der explizite Euler, in seiner kürzesten ehrlichen Form:

solver.py · euler_odeintZeilen 17–22
ys = [y0]
for i in range(t.shape[0] - 1):
    dt = t[i + 1] - t[i]                  # Schrittweite aus dem Zeitgitter
    dy = func(t[i], ys[-1])              # Steigung am aktuellen Punkt
    ys.append(ys[-1] + dt * dy)         # ein Euler-Schritt vorwärts
return tf.stack(ys, axis=0)

Drei Zeilen Mathematik. func ist das ODEFuncModel aus Abschnitt 01; y0 ist der Startzustand, t das Zeitgitter. Die Engine dieser Lernreihe hat exakt dieselbe Funktion als eulerOdeint. Code · solver.py

Expliziter Euler · ein Schrittklassisch

Der Euler ist die einfachste denkbare Integration: nimm die Steigung am Startpunkt und gehe ein Stück Δt in diese Richtung. Das ist exakt, wenn die Bahn eine Gerade wäre — und sie ist es nie. Der Fehler pro Schritt wächst mit der Krümmung und mit Δt. Im Training ist das absichtlich so: der Solver ist Teil des Modells, das Netz lernt die Ableitung, die diesem Euler die richtige Bahn beschert.

Warum kein @tf.function, kein adaptiver Solver

Der Code baut die Bahn mit einer Python-Schleife und tf.stack, im Eager Mode Code · solver.py:15. Kein adaptiver Schrittweiten-Regler, keine RK4-Korrektur. Das hält die Berechnung durchschaubar und den Gradienten kurz — der Preis ist der Euler-Fehler, den das nächste Lab sichtbar macht.

Im Lab baust du die Bahn selbst auf. Wähl ein System, setz die Schrittzahl klein (grobes Δt) und sieh, wie die Euler-Bahn von der feinen Referenz abdriftet. Mehr Schritte → kleineres Δt → die Bahnen fallen zusammen.

euler_odeint · Schritt für Schritt zur Bahngrob vs. fein
Schrittweite Δt —
NRMSE gegen Referenz —
Referenz: feine RK4-Bahn (= scipy DOP853 im Code).
Setz die Schrittzahl auf das Minimum: die Euler-Bahn (Punkte) schneidet die Kurven der echten Bahn ab — der NRMSE steigt. Schieb die Schrittzahl hoch: Δt schrumpft, der Fehler fällt gegen null. Das ist genau der Forward-Pass des Trainings.

03  Trainingsfenster schneiden

get_batch: kurze Fenster statt der ganzen Bahn

Auf der vollen Trajektorie über 1000 Punkte zu trainieren wäre teuer und liefert nur ein einziges Lernsignal pro Schritt. Stattdessen schneidet get_batch Code · trainer.py:11 bei jeder Iteration batch_size zufällige Startpunkte und nimmt von dort jeweils ein batch_time Schritte langes Stück heraus:

trainer.py · get_batchZeilen 27–39
data_size = len(t)
s = rng.choice(data_size - batch_time, batch_size, replace=False)  # zufällige Starts

y0 = y[s][:, np.newaxis, :]                       # (batch_size, 1, 2): Startzustände
t_batch = t[:batch_time]                          # IMMER t[:batch_time] (autonom)
y_batch = np.stack(
    [y[s_i:s_i + batch_time, np.newaxis, :] for s_i in s], axis=1
)  # (batch_time, batch_size, 1, 2): Ziel-Teilbahnen
return y0, t_batch, y_batch

Zwei Feinheiten: die Starts werden ohne Zurücklegen gezogen (replace=False), und das Zeitgitter ist immer t[:batch_time] — weil die Systeme autonom sind, zählt nur die Länge des Fensters, nicht seine absolute Position. Code · trainer.py

Formen der drei Rückgabewerte von get_batch. Code · trainer.py:33-37

Im Loop wird genau dieses y0 durch euler_odeint über t_batch gerollt und das Ergebnis mit y_batch verglichen. Jede Iteration sieht also andere Ausschnitte der Bahn — das gibt dem Optimierer Vielfalt, ohne je die volle Trajektorie zu integrieren.

Das Lab zeigt die volle Trajektorie als Zeitreihe und hebt batch_size zufällige Fenster der Länge batch_time hervor. Die Auswahl ist deterministisch über einen Seed — derselbe Seed, dieselben Fenster, exakt wie rng.choice im Code.

04  Der Gradientenschritt

GradientTape, Clipping, Adam

Jetzt fügt sich alles zusammen. Pro Iteration: ein Batch ziehen, vorwärts integrieren, den Verlust messen, den Gradienten zurückrechnen, optional clippen, einen Adam-Schritt machen. Der Kern des Loops Code · trainer.py:71, wörtlich:

trainer.py · train (Loop-Kern)Zeilen 77–95
with tf.GradientTape() as tape:
    pred = euler_odeint(model, y0_tf, t_tf)        # Forward-Pass = Integration
    loss_value = loss_fn(pred, y_true)                # MSE(pred, ziel)

grads = tape.gradient(loss_value, model.trainable_variables)
if clip_norm:
    applied_grads, pre_clip_norm = tf.clip_by_global_norm(grads, clip_norm)
else:
    applied_grads = grads
if gradient_tracker is not None and gradient_tracker.should_log(itr):
    gradient_tracker.record(itr, model, grads)        # RQ4: pre-clip Norm protokollieren
    if clip_norm:
        gradient_tracker.record_clip(itr, float(pre_clip_norm.numpy()), clip_norm)
optimizer.apply_gradients(zip(applied_grads, model.trainable_variables))

Fünf hervorgehobene Zeilen sind das ganze Lernen. Der Rest ist Buchhaltung für den Gradient-Tracker. Code · trainer.py

Geh die fünf Schritte einzeln durch — jeder hat einen klaren Zweck:

Verlust · MSE über das FensterCode · trainer.py:6

1 · GradientTape. Das with tf.GradientTape() zeichnet jede Operation auf, die loss_value berührt — einschließlich aller batch_time Euler-Schritte. Genau deshalb ist ein kurzer Solver gut: der Tape muss durch die ganze Integration zurückdifferenzieren. Das ist das Backprop-through-time aus Vorlesung 01, nur dass die „Zeitschritte“ hier Euler-Schritte sind.

2 · Loss. loss_fn ist im Benchmark MSE Code · trainer.py:6: der mittlere quadratische Abstand zwischen der gerollten Bahn pred und der echten Teilbahn y_true. 'mae' existiert als Alt-Option, wird im Thesis-Lauf aber nicht genutzt.

3 · tape.gradient. Der Tape liefert ∂L/∂θ für alle trainierbaren Variablen — die Gewichte der drei Schichten und die Zell-Parameter. Diese rohen Gradienten gehen unverändert an den Tracker, damit RQ4 die echte Pathologie sieht Code · trainer.py:88.

4 · clip_by_global_norm. Optional. Ist clip_norm gesetzt, wird der globale Gradient (alle Variablen als ein langer Vektor) auf diese Norm skaliert, falls er sie übersteigt. Das ist der Schalter, der den v1- vom v2-Lauf trennt — dazu gleich der eigene Abschnitt.

5 · Adam. optimizer.apply_gradients macht einen Adam-Schritt mit Lernrate 1e-3. Adam skaliert jede Komponente mit ihren laufenden ersten und zweiten Momenten — robust gegen unterschiedlich große Gradienten der verschiedenen Parameter klassisch.

Der Gradient-Tracker — warum vor dem Clip protokolliert wird

Alle log_every = 25 Iterationen ruft der Loop tracker.record auf Code · gradient_flow.py:36. Aufgezeichnet werden die rohen Gradienten — vor dem Clipping. So zeigt RQ4 die echte Gradientenpathologie der Zellen (Vanishing/Exploding aus Vorlesung 01), während record_clip separat festhält, wann und wie hart der Clip eingriff.

Aus dieser Spur entsteht in Vorlesung 09 der Gradient-Flow-Plot.

05  v1 gegen v2

Gradient-Clipping: derselbe Code, ein Schalter

Der Benchmark läuft in zwei Profilen. v1 trainiert die liquiden Kernzellen ohne Clipping (clip_norm = 0.0, also None). v2 setzt clip_norm = 1.0 und isoliert damit, ob das Clipping allein die Instabilität der Roh-Zellen behebt Code · run_benchmark.py:62.

clip_by_global_normklassisch

Lies die Formel: solange die globale Norm ‖g‖ unter c bleibt, ist der Faktor 1 — nichts passiert. Übersteigt sie c, wird der ganze Gradient auf Länge c zurückskaliert, Richtung bleibt erhalten. Ein einzelner explodierender Schritt kann das Training so nicht mehr aus der Bahn werfen.

Das Lab zeigt eine synthetische Gradientennorm-Folge mit gelegentlichen Spitzen. Schieb die Schwelle c und sieh, wie der angewandte Gradient gedeckelt wird — und wie oft der Clip in v2 (c = 1.0) tatsächlich greift.
