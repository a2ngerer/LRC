Drei Figuren erzählen das ganze Experiment

Vorlesung 07 hat die sechs ODE-Systeme gezeigt, Vorlesung 08 den Trainings-Code. Jetzt kommt das, was am Ende auf der Festplatte landet: drei Bildtypen, die deine plot_results.py aus jeder Lauf-JSON erzeugt. Wer sie lesen kann, liest das Ergebnis.

Der wichtigste Typ ist das Phasenporträt: keine Zeitachse, sondern der Zustand (y₀, y₁) gegen sich selbst aufgetragen. Bei Lotka-Volterra zeichnet das eine geschlossene Schleife — Beute und Räuber jagen sich im Kreis. Die graue Bahn ist die Wahrheit, die orange die Vorhersage des Modells. Je dichter beide liegen, desto kleiner der Fehler. Das Versprechen dieser Seite: du siehst die orange Bahn entstehen.

Ehrlichkeit zuerst — bitte vor den Labs lesen

Im Browser wird nichts trainiert. Die echten Ergebnisse stammen aus einem auf dem Cluster trainierten RNN (run_benchmark.py, 2000 Iterationen Adam). Diese Seite kann das nicht nachrechnen — sie hat keine gelernten Gewichte.

Stattdessen wird die wahre Trajektorie faithful integriert (dieselbe Mathematik wie im Code) und die Vorhersage illustrativ erzeugt: als zweiter Euler-Rollout mit einer leicht gestörten Dynamik, die ein unvollkommen gelerntes Modell vertritt. Der Slider „Trainingsfortschritt“ morpht diese gestörte Dynamik zur wahren — die Vorhersage wandert sichtbar auf die Wahrheit zu und der NRMSE fällt. Das ist eine Nachstellung des Lernens, kein echtes Training.

01  Woher die orange Bahn kommt

Die Vorhersage ist ein Euler-Rollout ab y[0]

Im Code heißt der entscheidende Schritt evaluate_full_trajectory. Er nimmt das trainierte Modell, setzt es auf den ersten wahren Zustand y[0] und lässt es über das ganze Zeitgitter laufen — Schritt für Schritt, jeder neue Punkt aus dem vorigen Code · run_benchmark.py:118:

run_benchmark.py · evaluate_full_trajectoryZeilen 118–128
def evaluate_full_trajectory(model, t, y):
    """Roll out the trained model from y[0] over the full time grid."""
    y0 = tf.constant(y[0][np.newaxis, np.newaxis, :], dtype=tf.float32)
    t_tf = tf.constant(t, dtype=tf.float32)
    pred = euler_odeint(model, y0, t_tf)          # (T, 1, 1, 2)
    pred_traj = pred.numpy().reshape(len(t), -1)  # (T, 2)
    return {
        'mse':   mse(y, pred_traj),
        'nrmse': nrmse(y, pred_traj),
        'trajectory_pred': pred_traj.astype(float).tolist(),
    }

Nur der erste Punkt ist „geschenkt“. Alles danach erzeugt das Modell aus sich selbst — ein Fehler im Schritt i pflanzt sich in i+1 fort. Deshalb ist der Rollout der ehrliche Test. Code · run_benchmark.py

Der Integrator dahinter ist ein nackter Euler-Schritt — derselbe, der im Browser unter dem Namen eulerOdeint läuft Code · solver.py:

euler_odeint · ein SchrittCode

Bei der wahren Bahn ist f die echte Systemdynamik (im Browser RK4-fein als Referenz). Bei der Vorhersage ist f die gelernte Dynamik des RNN. Lernt das Modell perfekt, fallen beide Bahnen zusammen. Genau diesen Annäherungsprozess stellt das nächste Lab nach.

02  Das Herzstück

Das Phasenporträt zieht sich auf

Jetzt der Aufbau in Zeitlupe. Wähl ein System — voreingestellt ist Lotka-Volterra. Die graue Schleife ist die wahre Bahn, sie wächst Punkt für Punkt im (y₀,y₁)-Raum. Die orange Bahn ist die illustrative Vorhersage, ein zweiter Rollout. Mit Trainingsfortschritt = 0 startet sie auf einer verzerrten Dynamik und zieht eine völlig andere Schleife; schiebst du auf 1, morpht ihre Dynamik zur wahren — die orange Bahn legt sich auf die graue und der NRMSE fällt mit.

So zeichnet plot_phase_portraits es im Code: grau in '0.6' für die wahre Bahn, 'C3' (rot-orange) für die Vorhersage, der NRMSE im Titel Code · plot_results.py:103.

Schieb den Trainingsfortschritt von 0 auf 1: die orange Vorhersagebahn legt sich auf die graue Wahrheit, der NRMSE fällt. Im echten Experiment kommt diese Annäherung aus 2000 Adam-Schritten eines RNN — hier wird sie durch Annähern der Dynamik nachgestellt.

Wahre Bahn: RK4-fein (im Code scipy-Solver). Vorhersage: eulerOdeint mit gestörter, zum Wahren morphender Dynamik. NRMSE faithful zu metrics.py. Code · plot_results.py / run_benchmark.py

Lies die Zeitreihe darunter mit

Das kleine Band unter dem Phasenraum zeigt dieselben zwei Komponenten gegen die Zeit. Beim periodischen Räuber-Beute-System sieht man dort die phasenverschobenen Wellen — Beute steigt, Räuber folgt verzögert. Phasenporträt und Zeitreihe sind zwei Sichten auf dasselbe Rollout; der Code speichert nur die Trajektorie, beide Plots fallen daraus.

03  Warum die y-Achse logarithmisch ist

Die Lernkurve fällt — in Log-Skala

Die zweite Figur ist die Lernkurve: der Trainings-MSE über die Iteration, gemittelt über die Seeds. Der eine Befehl, der sie lesbar macht, ist ax.set_yscale('log') Code · plot_results.py:57. Ohne Log-Achse drückt der riesige Anfangsfehler die ganze spätere Feinarbeit in eine flache Linie am Boden.

plot_results.py · plot_loss_curvesZeilen 71–80
histories = [r['training']['loss_history'] for r in group]
n = min(len(h) for h in histories)
mean = np.mean([h[:n] for h in histories], axis=0)  # Mittel über Seeds
ax.plot(mean, STYLES[wiring], color=colors[cell],
        label=f'{cell} / {wiring}', linewidth=1.2)
ax.set_yscale('log')                          # der entscheidende Befehl
ax.set_xlabel('Iteration'); ax.set_ylabel('Training loss (MSE)')

Linienstil aus STYLES = {'dense':'-', 'ncp':'--'} — durchgezogen für dense, gestrichelt für NCP Code · plot_results.py:27.

Im Lab siehst du die Kurve in beiden Skalen. Schalte zwischen linear und log um: in linear verschwindet die spätere Verbesserung; in log wird jede Größenordnung sichtbar — ein Abfall von 10⁻¹ auf 10⁻³ ist genauso hoch wie der von 10⁰ auf 10⁻².

Stell die Achse auf linear: nach den ersten paar hundert Iterationen sieht alles gleich „fertig“ aus. Zurück auf log — und der lange, langsame Abstieg über drei Größenordnungen wird sichtbar. Genau deshalb steht im Code set_yscale('log').

04  Der dritte Figurentyp

Gradient-Flow: pro Schicht eine Norm

Die dritte Figur gehört zu RQ4 — dem Vanishing-Gradient aus Vorlesung 01. Der GradientFlowTracker notiert alle 25 Iterationen pro Schicht die globale Gradienten-Norm Code · gradient_flow.py:39; plot_gradient_flow trägt diese Normen über die Iteration auf — wieder in Log-Skala, eine Linie pro Schicht Code · plot_results.py:125.

Schichtnamen sind <index>_<Klassenname>, etwa 0_RNN oder 1_SparseLinear — so lassen sich bei einem NCP die inter-, command- und motor-Schichten auseinanderhalten Code · gradient_flow.py:57. Liegt eine Schicht-Norm um Größenordnungen unter den anderen, erreichen die Gradienten sie kaum — das ist das Vanishing-Signal, das die liquiden Zellen entschärfen sollen.

Die Skizze unten zeigt das Muster schematisch: pro Schicht eine fallende Norm, log-y. Dreh den Vanishing-Faktor hoch und sieh, wie sich die tiefe Schicht von den oberen ablöst.

Gradient-Flow-Skizze · Norm pro Schicht (log-y)schematisch
Norm-Spanne unten ↔ oben — Dekaden

Mit kleinem Vanishing-Faktor liegen alle Schicht-Normen dicht beieinander — gesunder Fluss. Dreh ihn hoch: die tiefste Schicht sackt um mehrere Dekaden ab und löst sich von den oberen. Genau das macht der echte Plot mit den gemessenen Normen sichtbar.

Schematische Schicht-Normen (keine gemessenen Werte): geometrischer Abfall je Schicht, log-y, NCP mit mehr Schichten als dense. Form 1:1 wie plot_gradient_flow. Code · plot_results.py:125 / gradient_flow.py

Wohin als Nächstes

Ein NRMSE pro Lauf ist eine Zahl unter vielen — fünf Seeds, vier Zellen, zwei Verschaltungen, sechs Systeme. Vorlesung 10 macht aus diesem Schwarm eine belastbare Aussage: Wilcoxon, Bonferroni, Cohen's d.
