01  Vom Vektorfeld zur Bahn

Wie aus ẏ = f(y) eine Kurve wird

Jedes der sechs Systeme ist ein autonomes Differentialgleichungssystem: Die Änderungsrate hängt nur vom aktuellen Zustand ab, nicht direkt von der Zeit. Der Zustand y = (y₀, y₁) ist zweidimensional — etwa Beutebestand und Räuberbestand. Die rechte Seite f ordnet jedem Zustand einen Geschwindigkeitsvektor zu klassisch:

Anfangswertproblem (gemeinsame Form aller 6 Systeme)klassisch

Das Vektorfeld allein ist statisch — ein Pfeil an jedem Punkt der Ebene. Eine Trajektorie entsteht erst, wenn man an einem Startpunkt y₀ beginnt und den Pfeilen folgt. Genau das tut ein numerischer Integrator: Er nimmt den aktuellen Punkt, liest die lokale Steigung f(y) ab und macht einen kleinen Zeitschritt in diese Richtung. Das einfachste Verfahren ist der explizite Euler-Schritt Code · solver.py:21:

Ein Euler-Schritt — so wandert der PunktCode · solver.py
Zwei Solver, ein Zweck

Für die ground truth reicht der grobe Euler nicht — kleine Schrittfehler summieren sich. Deshalb erzeugt datasets.py die Referenzbahn mit dem hochpräzisen Verfahren DOP853 (Runge-Kutta 8. Ordnung) und adaptiver Schrittweite Code · datasets.py:81. Das Netz dagegen wird später absichtlich mit dem schlichten euler_odeint gerollt, damit Solver-Genauigkeit nicht das Ergebnis verfälscht — dazu Vorlesung 08.

Die Bahn ist also doppelt motiviert: einmal als möglichst exakte Wahrheit, einmal als faire, simple Vorhersage-Mechanik.

Im Lab unten siehst du diesen Übergang direkt. Setz den Startpunkt, lass den Integrator Schritt für Schritt laufen — und beobachte, wie aus einzelnen Euler-Sprüngen die glatte Trajektorie wird, die das System beschreibt.

Integrator-Werkstatt · ein Schritt nach dem anderenläuft
Schritt 0
Position —
Pfeil = Δt·f(y) am aktuellen Punkt.
Dreh Δt klein: viele kurze Sprünge, glatte Bahn. Dreh es groß: der Punkt schießt über die Kurve hinaus — sichtbarer Integrationsfehler. Genau deshalb nutzt der Datensatz den feinen DOP853, nicht diesen Euler.

03  Generierung im Detail

Formel neben Code: solve_ivp erzeugt den Datensatz

Jetzt die Brücke zwischen Mathematik und Implementierung an einem konkreten Beispiel. Die Lotka-Volterra-Gleichung beschreibt Beute y₀ und Räuber y₁: Beute vermehrt sich, wird aber durch Begegnungen mit Räubern dezimiert; Räuber sterben ohne Beute aus, gewinnen aber an jeder Begegnung klassisch.

periodic_predator_prey · Lotka-VolterraCode

Im Code ist das exakt diese Funktion — und der Aufruf von solve_ivp, der die Formel über 1000 gleichmäßig verteilte Zeitpunkte integriert Code · datasets.py:

datasets.py · ODE-Funktion + GenerierungZeilen 30–90
# die rechte Seite: dy = f(t, y) — hier Lotka-Volterra
def _periodic_predator_prey(t, y):
    return [1.5 * y[0] - 1.0 * y[0] * y[1],   # Beute
            -3.0 * y[1] + 1.0 * y[0] * y[1]]  # Räuber

def generate_dataset(name, data_size=1000):
    params = _SYSTEMS[name]                       # y0 + t_span
    t_eval = np.linspace(params['t_span'][0],
                         params['t_span'][1], data_size)   # 1000 Stützstellen
    sol = solve_ivp(_ODE_FUNCS[name], params['t_span'], params['y0'],
                    method='DOP853', t_eval=t_eval,
                    rtol=1e-3, atol=1e-6)
    t = sol.t        # (1000,)
    y = sol.y.T      # (1000, 2) — transponiert
    return t, y

Die hervorgehobenen Zeilen sind der ganze Trick: solve_ivp nimmt die Formel, den Startwert und die Zeitspanne und liefert eine Matrix der Form (1000, 2) — das ist der Datensatz, an dem alle Zellen trainieren. Code · datasets.py:77-89

Worauf die drei Zahlen stehen

DOP853 ist ein explizites Runge-Kutta-Verfahren 8. Ordnung — deutlich genauer als der Euler aus Abschnitt 01. rtol = 1e-3 und atol = 1e-6 sind die relative und absolute Fehlertoleranz, mit denen der Solver seine Schrittweite adaptiv wählt. data_size = 1000 legt fest, an wie vielen gleichmäßig verteilten Zeitpunkten die Bahn ausgewertet wird Code · datasets.py.

Wichtig: t_eval bestimmt nur, wo abgelesen wird — die Genauigkeit der Integration steuern allein die Toleranzen.

Didaktische Vereinfachung

Der echte Datensatz entsteht im Code mit scipy.solve_ivp(method='DOP853'). Für die hier gezeigten gutmütigen Systeme liegen beide praktisch übereinander; die Form der Kurven stimmt überein. 04  Die Fehlermetrik

Was bedeutet NRMSE — und warum nicht einfach MSE?

Hat das Netz eine Vorhersage geliefert, braucht man eine einzige Zahl, die sagt: wie weit daneben? Der naheliegende Kandidat ist der mittlere quadratische Fehler. Das Problem: er hängt am Wertebereich. Eine Spirale lebt im Bereich ±0.5, ein Räuber-Beute-System kann Werte über 3 erreichen. Derselbe absolute Fehler bedeutet bei beiden etwas völlig Verschiedenes — ein MSE wäre systemübergreifend nicht vergleichbar.

Deshalb normiert deine Metrik den RMSE durch die Spannweite der wahren Werte Code · metrics.py:11:

NRMSE · normalisierter RMSECode · metrics.py
metrics.py · nrmseZeilen 11–21
def nrmse(y_true, y_pred, epsilon=1e-12):
    rmse = np.sqrt(np.mean((y_true - y_pred) ** 2))
    value_range = float(np.max(y_true) - np.min(y_true))
    return float(rmse / (value_range + epsilon))

Durch das Teilen durch max − min wird der Fehler dimensionslos und relativ zur Größe des Systems. Ein NRMSE von 0.05 heißt grob: der typische Fehler ist 5 % der gesamten Wertespanne — egal ob Spiral oder Lotka-Volterra. Code · metrics.py

Im Lab siehst du das live. Eine Vorhersage wird künstlich verschlechtert — durch Rauschen und einen Skalierungsfehler. Der NRMSE läuft mit. Bei null Störung liegt er bei null; je weiter die Vorhersage abdriftet, desto größer wird er.

05  Wozu das Ganze

Sechs Systeme × der Rest: das v1-Raster

Diese sechs Systeme sind eine Achse eines größeren Versuchsplans. Der erste vollständige Durchlauf v1 kombiniert sie mit den Zelltypen, den Verschaltungen und mehreren Zufalls-Seeds zu insgesamt 240 Läufen — vier Zellen mal zwei Wirings mal sechs Systeme mal fünf Seeds Code · v1-Run:

Umfang des v1-BenchmarksCode

Die fünf Seeds pro Kombination sind kein Luxus: Neuronale Netze starten zufällig, ein einzelner Lauf ist verrauscht. Erst der Median über mehrere Seeds wird zu einer belastbaren Zahl. Die sechs Systeme liefern Breite — eine Zelle, die nur auf der linearen Spirale glänzt, aber an der nichtlinearen Räuber-Beute-Dynamik scheitert, fällt im Raster auf.

Wohin als Nächstes

Der Datensatz steht, die Metrik ist klar. Die nächste Vorlesung 08 · Der Trainings-Code zeigt, was zwischen ground truth und NRMSE passiert: wie euler_odeint die Zelle durch die Zeit rollt, wie der Adam-Optimierer die Gewichte zieht und warum der Gradient unterwegs getrackt wird.
