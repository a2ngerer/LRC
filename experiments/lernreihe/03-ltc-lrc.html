01  Die liquide Zeitkonstante

LTC: der Leitwert hängt am Signal

Das Liquid Time-Constant Network Paper · Hasani2020 nimmt die Membran-ODE und macht eine Sache anders als das CT-RNN: der synaptische Leitwert ist keine Konstante, sondern eine sigmoide Funktion des Zustands und der Eingabe. In der Hodgkin-Huxley-Schreibweise, die dein Code umsetzt Code · ltc_cell.py:

LTC · Conductance-ODE (Membranform)Code

Lies den markierten Term: Jede Synapse trägt einen Leitwert g_j(v) bei, der über ein Sigmoid auf- und zudreht, je nach Spannung. Damit ist der Gesamtleitwert g(v) = g_leak + Σ g_j(v) selbst zustandsabhängig — und mit ihm die effektive Zeitkonstante. In der kompakten Skalarform, die das Lab rechnet:

LTC · kompakte ODE + effektives τPaper

Je stärker die Synapse f(v,x) = σ(w·x+…) feuert, desto kleiner wird τ_sys — das Neuron reagiert blitzschnell. Bei stiller Eingabe wird es träge. Genau das fehlt dem CT-RNN mit seinem festen τ.

Die gelernten Parameter starten in engen Bereichen, die deine Implementierung fest vorgibt Code · ltc_cell.py:41 — das ist kein Detail, sondern Teil der Stabilität:

02  Warum 6 Schritte pro Schritt

Der fused Solver: Stabilität gegen Rechenzeit

Der liquide Leitwert ist nach oben unbeschränkt: feuern viele Synapsen, wird g riesig und τ = 1/g winzig. Ein winziges τ in einem System, das in groben Schritten Δt integriert wird — das ist eine steife ODE, und ein naiver expliziter Euler beginnt zu schwingen (siehe Vorlesung 00).

Deine LTC umgeht das mit zwei Maßnahmen, beide direkt im Code sichtbar: einem fused (semi-impliziten) Euler und einer Entfaltung in ode_unfolds = 6 Teilschritte Code · ltc_cell.py:213:

ltc_cell.py · _ode_solverZeilen 213–246
# cm/dt ist über die Teilschritte konstant -> einmal vorberechnen
cm_t = self._params["cm"] / (elapsed_time / self._ode_unfolds)

for t in range(self._ode_unfolds):          # 6 Teilschritte
    w_activation  = self._params["w"] * self._sigmoid(v_pre, mu, sigma)
    rev_activation = w_activation * self._params["erev"]
    w_numerator   = reduce_sum(rev_activation) + w_numerator_sensory
    w_denominator = reduce_sum(w_activation)   + w_denominator_sensory

    numerator   = cm_t * v_pre + gleak * vleak + w_numerator
    denominator = cm_t + gleak + w_denominator
    v_pre = numerator / (denominator + epsilon)   # semi-implizit: v steht im Nenner
return v_pre

Der Trick steckt in den hervorgehobenen Zeilen: v_pre taucht im Nenner auf. Dadurch kann der Schritt nicht überschießen — der Leitwert „bremst sich selbst“. Code · ltc_cell.py

Was „semi-implizit“ konkret heißt

Explizit wäre v ← v + Δt·v̇(v) — die Steigung am Startpunkt, blind extrapoliert. Semi-implizit löst stattdessen v ← (v + Δt·Antrieb)/(1 + Δt·Leitwert) nach v auf: ein großer Leitwert vergrößert den Nenner und dämpft den Schritt automatisch. Deshalb bleibt die Integration stabil, wo der explizite Euler explodiert.

Im Lab siehst du beides nebeneinander. Dreh die Schrittweite Δt und die Steifheit hoch und vergleiche: der explizite Euler kippt, der fused bleibt glatt — und mehr unfolds machen selbst den expliziten zahmer (kleinere Teil-Schritte).

Solver-Stabilität · explicit vs. fusedstabil
Stabilitätsmaß (1/τ+g)·Δt/U
0.00 < 2 → stabil
Setz Solver auf explicit, U=1: dreh Δt & g hoch, bis das Maß über 2 springt — Explosion. Erhöhe dann unfolds oder schalte auf fused: dieselben Werte, glatt. Das ist der Preis der LTC.

Explicit Euler ist nur stabil, solange (1/τ+g)·Δt/U < 2. Mehr unfolds U verkleinern den Teilschritt; der fused Solver hat die Schranke gar nicht. Paper · Hasani2020

03  Auch die Kapazität wird liquid

LRC: Sättigung und liquid elastance

Liquid-Resistance Liquid-Capacitance Paper · farsang2024liquid erweitert die LTC um zwei Zutaten, die das Schwingen an der Wurzel packen. Erstens Sättigung: Antrieb und Zerfall laufen durch tanh bzw. σ und können nicht mehr unbeschränkt wachsen. Zweitens liquid elastance ε — eine gelernte, zustandsabhängige reziproke Kapazität. Die Update-Regel aus deinem Code, in der forget-gate-Form Code · lrc_cell.py:229:

LRC · explicit-Euler-Update mit Elastance-GateCode
lrc_cell.py · _ode_solver (forget_gate, asymmetric)Zeilen 229–280
dt = elapsed_time / self._ode_unfolds        # ode_unfolds = 1 genügt
for t in range(self._ode_unfolds):
    # Elastance: gelerntes Gate aus [x, v], in (0,1), skaliert dt
    x = concat([inputs, v_pre]);  elastance_t = sigmoid(self.elastance_mapping(x)) * dt
    syn = self._sigmoid(v_pre, mu, sigma)
    g = gleak + reduce_sum(h * syn) + sensory_h          # Antriebs-Leitwert
    f = gleak + reduce_sum(w * syn) + sensory_w          # Zerfalls-Leitwert (forget)
    v_prime = -v_pre * sigmoid(f) + vleak * tanh(g)   # beide Terme gesättigt
    v_pre = v_pre + elastance_t * v_prime                  # explicit Euler
return v_pre

Der Clou: ε(x,v)·Δt verkleinert die effektive Schrittweite zustandsabhängig dort, wo die Dynamik sonst überschießen würde — ein gelerntes „Sanft-machen“. Code · lrc_cell.py

Kern-Insight LRC vs. LTC — direkt aus deiner Thesis

Dieses ε(w_i) ist genau der Mechanismus, den RQ2 und RQ5 isolieren wollen: Treibt die liquid elastance den Performance-Unterschied? Ohne aktivierte Elastance (ε = 1, elastance_type auf konstant) fällt LRC auf eine gesättigte LTC zurück.

Im Lab legst du genau diesen Schalter um — und siehst, wie aus „ruhigen Händen“ ein nervöseres LTC-artiges Verhalten wird.

Spiel mit dem Elastance-Schalter: dasselbe Signal, einmal mit liquid elastance (blau, ruhig), einmal ohne (ε = 1, sprunghafter). Dazu der Vergleich gegen eine LTC unter demselben Rauschen.

Elastance-Schalter · LRC vs. saturierte LTCε aktiv

Stell Verrauscht ein. Mit ε an glättet die LRC das Zappeln; schalt ε aus → sie fällt auf die saturierte LTC zurück und wird unruhiger. Das ist der Effekt, den RQ2/RQ5 messen.

Blau: LRC mit liquid elastance. Hell: LRC ohne ε (= saturierte LTC). Gestrichelt: Eingangssignal. Code · lrc_cell.py
