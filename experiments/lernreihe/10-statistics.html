01  Immer Apfel mit Apfel

Gepaarte Vergleiche: gleiches System, gleicher Seed

Der erste und wichtigste Schritt passiert, bevor irgendein Test läuft. Zwei Zellen werden nie über pauschale Mittelwerte verglichen, sondern Lauf gegen Lauf auf identischer Bedingung. Konfiguration A und Konfiguration B werden auf (system, seed) zusammengeführt — jeder Wert von A hat genau einen Partner von B unter exakt denselben Startbedingungen Code · aggregate_results.py:91.

aggregate_results.py · _paired_vectorsZeilen 91–96
def _paired_vectors(df, key_a, key_b):
    """Metric vectors for two configs, paired on (system, seed)."""
    a = df.loc[(df[list(key_a)] == pd.Series(key_a)).all(axis=1)]
    b = df.loc[(df[list(key_b)] == pd.Series(key_b)).all(axis=1)]
    merged = a.merge(b, on=['system', 'seed'], suffixes=('_a', '_b'))
    return merged[f'{METRIC}_a'].to_numpy(), merged[f'{METRIC}_b'].to_numpy()

Die hervorgehobene Zeile ist der Kern: ein merge auf system und seed. Ergebnis sind zwei gleich lange Vektoren, bei denen Position i in beiden dieselbe Bedingung meint. Code · aggregate_results.py

Warum nicht einfach die Mittelwerte vergleichen?

Manche Systeme sind für alle Zellen schwer (hoher NRMSE), andere für alle leicht. Vergleicht man nur die Gesamtmittel, mischt sich dieser „Schwierigkeits-Lärm“ in das Signal. Die Paarung subtrahiert ihn weg: Was zählt, ist die Differenz innerhalb desselben Paares — dort, wo System und Seed identisch sind, bleibt nur der Effekt der Zelle übrig. klassisch

Deshalb arbeiten alle folgenden Tests auf dem Differenzvektor diff = nrmse_A − nrmse_B, nicht auf den Rohwerten.

Im Lab siehst du diese Paarung direkt. Links steht jeder NRMSE-Wert von Zelle A, rechts der Partner von Zelle B; die Linie verbindet das Paar. Geht sie nach unten (B kleiner = besser), grün; geht sie nach oben, rot. Der Schieber „Effektstärke“ verschiebt B systematisch — beobachte, wie Cohen's d und die Mehrheit der Pfeil-Richtungen reagieren.

02  Der nichtparametrische Test

Wilcoxon signed-rank statt t-Test

Der klassische gepaarte t-Test unterstellt, dass die Differenzen normalverteilt sind. Für NRMSE-Differenzen gilt das nicht: einzelne Seeds kollabieren und erzeugen extreme Ausreißer (in deinen Daten etwa ltc periodic_predator_prey 0.41 ± 0.73), die Verteilung ist schief und schwerschwänzig Paper · research-questions. Ein Test, der Normalverteilung annimmt, liefert dann verzerrte p-Werte.

Deshalb verwendet die Auswertung den Wilcoxon signed-rank Test (scipy.stats.wilcoxon) — einen nichtparametrischen, gepaarten Test Code · aggregate_results.py:120 klassisch. Er fragt nicht „wie groß ist die Differenz?“, sondern nur:

Wilcoxon · Idee in einer Zeileklassisch

Die Differenzen werden nach Betrag sortiert und bekommen Ränge. Dann wird die Rangsumme der positiven gegen die der negativen Differenzen gestellt. Liegen Verbesserungen und Verschlechterungen zufällig durchmischt, sind beide Rangsummen ähnlich groß und p ist hoch. Häufen sich Verbesserungen auf der einen Seite, wird eine Rangsumme klein und p sinkt. Ein einzelner monströser Ausreißer kann das nicht kippen, weil nur sein Rang zählt, nicht sein Betrag.

Was Wilcoxon robust macht

Beim t-Test geht der Betrag jeder Differenz direkt in die Statistik ein — ein einziger Kollaps-Seed mit Differenz 2.0 dominiert. Wilcoxon ersetzt Beträge durch Ränge: Die größte Differenz bekommt Rang n, egal ob sie 0.3 oder 30 beträgt. Robust gegen Ausreißer, ohne Normalverteilung vorauszusetzen.

Genau deshalb steht im Code-Kommentar: „Wilcoxon signed-rank tests, alpha = 0.05, paired over (system, seed)“ — keine Wahl, sondern Konsequenz der Datenform. Code · aggregate_results.py:8-10

Im Lab erzeugst du einen Differenzvektor und schaltest einen Ausreißer dazu. Beobachte, wie die Vorzeichen-Mehrheit (die Wilcoxon-Intuition) stabil bleibt, während ein mittelwert-basierter Blick durch den Ausreißer sofort umkippt.

Setz einen echten Effekt nach rechts: Mehrheit grün, Mittelwert positiv. Jetzt dreh die Ausreißer-Größe hoch: der Mittelwert kippt ins Negative, die Vorzeichen-Mehrheit bleibt — Wilcoxon lässt sich vom einzelnen Kollaps nicht täuschen.

Balken: die einzelnen Differenzen pro Paar (grün positiv, rot negativ); der dicke Ausreißer-Balken ist der Kollaps-Seed. Synthetisch; die Robustheits-Eigenschaft ist die echte Begründung für die Testwahl. Wilcoxon 1945

03  Gegen das multiple Testen

Bonferroni: viele Tests, schärfere Schwelle

Wer 20 Vergleiche bei α = 0.05 rechnet, findet im Schnitt einen „signifikanten“ Unterschied rein durch Zufall — selbst wenn gar kein echter Effekt existiert. Das ist die Family-Wise Error Rate: Je mehr Tests in einer Familie, desto wahrscheinlicher mindestens ein falscher Treffer klassisch.

Dein Code testet Zelle gegen Zelle über alle Paare innerhalb einer Verdrahtung — das sind viele Tests pro Familie. Die Bonferroni-Korrektur hält die Gesamt-Fehlerrate, indem sie jeden rohen p-Wert mit der Anzahl der Tests multipliziert Code · aggregate_results.py:124:

Bonferroni · adjustierter p-WertCode
aggregate_results.py · _test_blockZeilen 106–127
n_tests = len(pairs)                       # Größe der Vergleichs-Familie
for label, key_a, key_b in pairs:
    x, y = _paired_vectors(df, key_a, key_b)
    stat, p = wilcoxon(x, y)              # roher p-Wert
    p_adj = min(1.0, p * n_tests)           # Bonferroni
    d = _cohens_d_paired(x, y)
    sig = 'YES' if p_adj < ALPHA else 'no'   # ALPHA = 0.05

Der adjustierte p-Wert wird bei 1.0 gekappt (ein p kann nie über 1 liegen). Das min(1.0, …) ist genau diese Kappung. Code · aggregate_results.py

Der Preis: kleinere Familien sind besser

Bonferroni ist konservativ — bei sehr vielen Tests wird die Schwelle so streng, dass auch echte Effekte durchfallen. Deshalb der Hinweis in der Auswertungs-Strategie: „kleinere m durch gezielte Vergleichsfamilien“. Nicht alles gegen alles testen, sondern nur die Vergleiche, die eine RQ wirklich braucht. 04  Wie groß ist der Effekt

Cohen's d: der p-Wert sagt nicht alles

Ein p-Wert beantwortet nur eine Ja/Nein-Frage: existiert ein Unterschied? Bei genug Daten wird fast jeder winzige Unterschied „signifikant“. Was er nicht sagt: ist der Unterschied groß genug, um zu zählen? Diese Lücke füllt die Effektgröße — bei gepaarten Daten Cohen's d Code · _cohens_d_paired klassisch.

Cohen's d (gepaart)Code
aggregate_results.py · _cohens_d_pairedZeilen 99–102
def _cohens_d_paired(x, y):
    diff = x - y
    sd = diff.std(ddof=1)
    return float(diff.mean() / sd) if sd > 0 else float('nan')

d ist das Verhältnis von mittlerer Differenz zu deren Streuung — ein dimensionsloses Maß. ddof=1 ist die Stichproben-Standardabweichung. Code · aggregate_results.py

d normiert den Effekt an der Streuung der Differenzen. Ein großes d heißt: die Verbesserung ist nicht nur im Mittel da, sie ist auch konsistent über die Paare. Genau so liest sich der dokumentierte Befund deiner Daten: der NCP-Einbruch ist mit d = −0.88 LRC-spezifisch (stark), während LTC mit d = −0.28 nicht signifikant ist (klein) Paper · research-questions.

Warum H1 beide braucht

H1 verlangt zweierlei zugleich: Signifikanz (Wilcoxon nach Bonferroni) und eine Mindest-Effektgröße — „Median-NRMSE-Reduktion ≥ 10 % gegenüber LSTM“. Der p-Wert allein würde einen statistisch sicheren, aber praktisch belanglosen 0,5-%-Vorteil als Erfolg verbuchen. Erst die Kombination aus p und d macht die Aussage belastbar.
